# fitloop-kb

> 运动营养知识服务：扫描件 → 结构化事实 → 三层检索 → 带页码的引用。
> 被 fitloop 作为知识后端接入（MCP），服务不可用时降级为纯计算。

---

## 1. 它解决什么

fitloop 算得准（热量区间、蛋白缺口、负荷），但解释不了「为什么」。
「膝盖疼能不能深蹲」「蛋白粉什么时候喝」这类问题只能靠模型自己说，**没有出处**。

这个服务只做一件事：**给出带页码的原文；答不了就说答不了。**

~~~
fitloop（Agent）──MCP──▶ fitloop-kb（知识服务）
  编排 / 数字 / 交互              语料 / 检索 / 引用 / 拒答
~~~

---

## 2. 四条设计原则

| 原则 | 怎么落实 |
|---|---|
| **知识归知识，判定归调用方** | `get_recommendation` 返回证据 + `decision_owner: caller` |
| **每条结果必须带 source + page** | 出处从结果里取，不在调用方写死 |
| **答不了就返回空** | 检索为空、模型判定答不了 → 都返回空，由调用方明说「没查到依据」 |
| **表格单独成块，正常参与索引** | 数值答案大量在表里，排除等于自断退路 |

---

## 3. 数据链路

~~~
扫描版 PDF（151 / 378 页，无文字层）
  → RapidOCR 带坐标（19.6 秒/页）
  → XY-Cut 版面分析（正文 / 表格 / 图表 三类）
  → 分块：609 块（正文 554 / 表格 45 / 图表 10），平均 197 字
  → LLM 抽成 455 条结构化事实（主体 / 别名 / 数值 / 单位 / 页码 / 周期）
~~~

抽取的每条都回原文校验：**值必须能在原块里逐字找到**，找不到就丢弃（609 块只丢了 1 条）。

### 为什么用规则型版面分析而不是 MinerU

书籍版式规整，XY-Cut（几何规则）+ 启发式块分类就够：零新增依赖、可解释、每条规则可追溯。

| 规则 | 做法 |
|---|---|
| 找中缝 | 文本框投影到 x 轴，找中间区域最宽的空白带 → 切左右栏 |
| 聚行 | 中心 y 差 < 半个行高才算同一行（扫描件有倾斜） |
| 表格 | 连续 ≥3 行、每行 ≥3 格、列位置对齐 → 还原 Markdown |
| 图表 | 连续 ≥4 个纯数字小块 → 判为坐标轴，丢弃，只留图注 |

## 4. 检索：三层，按代价从低到高

**一层不行才走下一层**，任何一层失败都不报错：

| 层 | 做法 | 耗时 | 30 题里的命中占比 |
|---|---|---|---|
| ① **别名精确匹配** | 455 条事实，问句里出现主体或别名就直接返回结构化结果 | **0 ms，不调模型** | 16/30（53%） |
| ② **无状态改写** | 别名没中，调一次模型把口语翻成书中用词（「动弹」→「身体活动」），再匹配 | ~1 s | 2/30 |
| ③ **BM25 + 向量 → RRF → 重排** | 中文 bigram 与 bge-small-zh 各取 30 条，RRF 融合，bge-reranker 精排到 5 条 | ~2 s | 兜底 |

向量那一路的余弦阈值卡在 **0.58**，低于它不算召回——否则 0.4 左右的无关块也会被带进来。

### 第四道：LLM 判「这条真能回答吗」

别名匹配的通病是**宽主体过度命中**：问「隔夜水能喝吗」，句子里有「水」就命中「水：1500~1700ml」。

所以返回前再判一次：候选丢给模型，问「哪些真能回答」，一条都不行就返回空。

**它的价值不是提升答对率，是降低错答率**：

| | 加筛前 | 加筛后 |
|---|---|---|
| 答对 | 16 | 16 |
| 拒答 | 3 | 11 |
| **错答** | **11** | **3** |

### 周期：每周的量要换算成每天

书里很多推荐量是**每周**的（鱼 300~500g/周、蛋 300~350g/周），用户问的却是「一天吃多少」。

事实表里存 `scope`（day / week / month）和 `per_day`（换算后的每日当量）：

~~~
鱼类 300~500g [week] → 约 43~71g/天
~~~

换算走代码，不靠模型猜；只对 g / ml / 克 / 毫升 换算，kg 和「次」「杯」不换算。

## 5. 判分器：这一节比检索更重要

### 5.1 为什么字面串匹配不够

最初判分是「答案字符串出现在 top5 就算对」，9 题跑出 7/9，看着还行。
人工核对发现：**两题是判分器误判，不是检索失败**。

~~~
问：每天应该喝多少水
top1 = p138「…每天可喝7~8杯水…适宜摄入量1700ml」  ← 这就是答案
但 gold 字符串是「1500~1700ml」，判分器不认
~~~

根因：**同一个数字会出现在完全不同的语义里**。300~500g 同时是蔬菜、鱼、奶的推荐量。

### 5.2 两段式判分

~~~
1. 主体锚定：块内必须出现该题的主体词集合（奶类/奶制品/乳制品/液态奶）
2. 邻近性：数值必须在主体词 window 字内，且中间不夹别的主体词
3. 否定排除：「不建议超过 X」不是推荐值
4. 表格特例：按表头列 → 该列取值，字符距离不适用
~~~

### 5.3 演进结果

| 判分器 | BM25@5 | BM25+Rerank@5 |
|---|---|---|
| 字面串 | 5/9 | 7/9 |
| + 主体锚定/邻近性 | 7/9 | **9/9** |
| + 表格列对齐 | 7/9 | 9/9 |
| + 否定词排除 | 7/9 | 9/9 |

**换判分器后重排仍然 +2，说明重排的价值是真的，不是判分器刷出来的。**

### 5.4 30 条判分用例 + 17% 标注错误

30 条用例分三类：同值不同主体、多数字邻近、否定语气。最终 30/30。

但过程中**我自己标错了 5 条**（全是凭记忆标的）：

| 用例 | 我标的 | 原文实际 |
|---|---|---|
| p72 大豆 | 表里有 25~35g | 表里是 105~175g（每周） |
| p148 水 | 有数值 | 没有任何数值 |
| p63 全谷物 | 不该算对 | 原文写「全谷物及杂豆50~150g」 |
| p43 运动 | 不该算对 | 原文写「每周150分钟以上」 |

**判分器 0 个 bug，5 个错全在标注。** 于是定了「标注即证据」：每条必须从块里逐字抓片段 + 记 chunk_id + 页码。

## 6. 对抗样例：测出 window 的边界

自然语料里没有边界，人工构造 18 条：

| 类别 | 构造 | 结果 |
|---|---|---|
| A 同值不同主体 | 「蔬菜300~500g，鱼禽300~500g」 | 5/5 |
| B 否定/上限 | 「不建议奶类超过300ml」 | 5/5（加否定词前 4/5） |
| C 表格跨行 | 表头一行、值一行，中间隔别的食物 | 5/5 |
| D 距离边界 | 主体与值之间插 10/45/80 字 | 2/3 |

| window | 通过 | 说明 |
|---|---|---|
| 30 | 16/18 | 够不着远距离的值 |
| **60** | **17/18** | 折中，唯一失败是 80 字极端构造 |
| 90 | 18/18 | 过了，但假阳性风险上升 |

## 7. 独立 30 题：这才是真成绩

前面那 9 题是我按书里的准则倒着出的，**问句措辞和原文高度重合**，等于在测自己的题库。

所以另起一套：**凭常识写 30 条真实问法，不看书、不看事实表**，跑完人工判。

| 结果 | 数量 | 说明 |
|---|---|---|
| **答对** | 16 | 菜 / 水果 / 牛奶 / 盐 / 油 / 糖 / 主食 / 粗粮 / 坚果 / 鱼 / 走多少步 / 晚上几点 / 咖啡 … |
| **拒答** | 11 | 隔夜水、不吃晚饭、空腹跑步、豆浆、孕妇、糖尿病、高血压 … |
| **错答** | **3** | 一周动弹→6000步、小孩吃肉→成人量、运动后喝水→每天量 |

**关键指标是错答数：加 LLM 筛选前 11 条，现在 3 条。**

拒答里 7 条是书里确实没有，4 条是覆盖不足（书里有但没抽到）——后者算已知缺口。

## 8. 已知限制（不藏）

| 限制 | 现状 |
|---|---|
| 语料只有 151 / 378 页 | 全书 OCR 约 2 小时，可断点续跑 |
| 独立题只有 30 条 | 答对 16、错答 3，其余拒答 |
| 第三层不拒答 | BM25 对中文 bigram 几乎总能匹配到东西，拒答只在事实层生效 |
| 向量在 30 题上没带来变化 | 八成走别名、其余多在事实层被筛空，落到第三层的极少 |
| 事实表有噪声 | 「生豆浆：5分钟」这类抽取错误还在，靠 LLM 筛选兜住 |
| 缺适用人群字段 | 事实里没存「成年人 / 4–7 岁」，小孩的问题会返回成人量 |
| 表格跨页未处理 | 续表会被切成两块 |
| 没有多语言 | 中文单语，英文对照行已剔除 |
| 每次查询 3–5 秒 | MCP 每次起进程重载模型；改常驻可解，未做 |
