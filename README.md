# fitloop-kb

> 运动营养知识服务：语料 → 检索 → 引用 → 拒答。被 fitloop 作为知识后端接入。
> 当前状态：**可运行的最小闭环**，评估集 9 题 + 30 条判分器用例 + 18 条对抗样例。

---

## 1. 它解决什么

fitloop 算得准（热量区间、蛋白缺口、负荷），但解释不了「为什么」——
「膝盖疼能不能深蹲」「蛋白粉什么时候喝」这类问题只能靠模型自己说，没有出处。

这个服务只负责一件事：**给出带页码的原文，答不了就说答不了。**

~~~
fitloop（Agent）  ──MCP client──▶  fitloop-kb（知识服务）
  编排 / 数字 / 交互                 语料 / 检索 / 引用 / 拒答
~~~

---

## 2. 四条设计原则

| 原则 | 为什么 |
|---|---|
| **知识归知识，判定归调用方** | `get_recommendation` 返回 `decision_owner: caller`，kb 不替谁做选择 |
| **每条结果必须带 source + page** | 没有出处的答案等于没有答案 |
| **检索为空就返回空** | 让调用方拒答，而不是让模型编 |
| **表格单独成块，正常参与索引** | 数值型答案大量在表里，排除等于自断退路 |

---

## 3. 数据链路

~~~
PDF(扫描件) → RapidOCR(带坐标) → XY-Cut 版面分析 → 块分类 → 分块入库
                                   ├─ 正文：按 y 聚行、x 聚列，左栏→右栏
                                   ├─ 表格：按行列还原（字符距离不适用）
                                   └─ 图表：坐标数字丢弃，只留图注
~~~

当前语料：**151 页 → 609 块**（正文 554 / 表格 45 / 图表 10），平均 197 字。

### 为什么用规则型版面分析而不是 MinerU

书籍 PDF 版式规整，XY-Cut（几何规则）+ 启发式块分类就够，
零新增模型依赖、可解释、每条规则可追溯。学习型版面模型（MinerU / PP-Structure）留给版式多变的场景。

## 4. 检索：四步，每步都有数字

| 步骤 | 做了什么 | 效果 |
|---|---|---|
| ① 版面分析 | 图表坐标数字剔除，表格还原成 Markdown | 答案块从畸形拼接变成干净文本 |
| ② 同义词扩展 | `喝水→饮水`、`吃盐→食盐` | 「水」从 **0 分（未进榜）→ 第 22 名** |
| ③ BM25 | 中文按字符 bigram | 基线 |
| ④ Cross-Encoder 重排 | bge-reranker-base，top-50 → top-5 | **整体上移**，见下表 |

### 排名迁移（9 题，答案块在检索结果里的名次）

| 题 | 裸 BM25 | +扩展 | +重排 |
|---|---|---|---|

| 奶类 | 44 | 44 | **7** |
| 水 | 未进榜 | 22 | 8 |

## 5. 判分器：这一节比检索更重要

### 5.1 从「字面串」到「主体锚定」

最初的判分是「答案字符串出现在 top5 里就算对」。9 题跑出 7/9，看着还行。
但人工核对发现：**两题是判分器误判，不是检索失败**。

~~~
问：每天应该喝多少水
top1 = p138「…每天可喝7~8杯水…适宜摄入量1700ml」   ← 这就是答案
但 gold 字符串是「1500~1700ml」，判分器不认
~~~

根因：**同一个数字会出现在完全不同的语义里**。`300~500g` 同时是蔬菜、鱼、奶的推荐量，字面一样，主体不同。

新判分器两段式：

~~~
1. 主体锚定：块内必须出现该题的主体词集合（奶类/奶制品/乳制品/液态奶）
2. 邻近性：数值必须在主体词 window 字内出现，且中间不夹别的主体词
3. 否定排除：「不建议超过 X」不是推荐值
4. 表格特例：按表头列 → 该列取值，字符距离不适用
~~~

### 5.2 演进结果

| 判分器 | BM25@5 | BM25+Rerank@5 | 备注 |
|---|---|---|---|
| 字面串 | 5/9 | 7/9 | 两题误判 |
| + 主体锚定/邻近性 | 7/9 | **9/9** | 无新误判 |
| + 表格列对齐 | 7/9 | **9/9** | 基线不变，表格题正确 |
| + 否定词排除 | 7/9 | **9/9** | 对抗样例 B 类 5/5 |

### 5.3 30 条判分器用例

设计三类：同值不同主体（A）、多数字邻近（B）、否定/限制语气（C），各 10 条。
结果 **30/30**，但——

> **这个 30/30 不代表验收通过。**
> 三档 window（30/60/90）全满分，说明这批题根本没压到边界。
> 我从语料里挑的块，主体和数值都挨得很近，window=30 也照样命中。

### 5.4 真正发现的问题：标注错误率 17%

30 条用例里，**我自己标错了 5 条**：

| 用例 | 我标的 | 原文实际 |
|---|---|---|
| p72 大豆 | 表里有 25~35g | 表里是 105~175g（每周） |
| p148 水 | 有数值 | 没有任何数值 |
| p63 全谷物 | 不该算对 | 原文写「全谷物及杂豆50~150g」 |
| p43 运动 | 不该算对 | 原文写「每周150分钟以上」 |
| p72 全谷物 | 选错块 | 表格块判对了，选块函数先匹到别的块 |

**判分器 0 个 bug，5 个错全在标注。**

于是定了「标注即证据」：每条用例必须从块里逐字抓片段 + 记 chunk_id + 页码，
人只判 expect，不许凭记忆写答案。修正后 30/30。

## 6. 对抗样例：终于测出了 window 的边界

自然语料里没有边界，就人工构造 18 条：

| 类别 | 构造 | 结果 |
|---|---|---|
| A 同值不同主体 | 「蔬菜300~500g，鱼禽300~500g」 | 5/5 |
| B 否定/上限 | 「不建议奶类超过300ml」 | 5/5（加否定词前是 4/5） |
| C 表格跨行 | 表头一行、值一行，中间隔别的食物 | 5/5 |
| D 距离边界 | 主体与值之间插 10/45/80 字 | 2/3 |

**window 敏感性（这次真的有区分度了）**：

| window | 通过 | 说明 |
|---|---|---|
| 30 | 16/18 | D 类只过 1/3，够不着远距离的值 |
| **60** | **17/18** | 折中，唯一失败是 80 字极端构造 |
| 90 | 18/18 | 过了，但假阳性风险上升 |

## 7. 已知限制（不藏）

| 限制 | 现状 |
|---|---|
| 语料只有 151 / 378 页 | 全书 OCR 约 2 小时，可断点续跑 |
| 评估集只有 9 题 | 样本太小，单题变化就能影响结论 |
| 标注错误率 17% | 扩到 150 题前必须先固化标注流程 |
| window=60 是折中不是最优 | 只有对抗样例能测出来，自然语料测不出 |
| 表格跨页未处理 | 续表会被切成两块 |
| 没有多语言 | 中文单语，英文对照行已剔除 |
