# 判分器演进 · 临时笔记

> 30 题验证已跑完。正式 README 等下一步再写。

## 两版判分器

| 版本 | 规则 | BM25@5 | BM25+Rerank@5 |
|---|---|---|---|
| 旧 | 字面串匹配 | 5/9 | 7/9 |
| 新 | 主体锚定 + 数值邻近 + **表格列对齐** + 竞争主体排除 | **7/9** | **9/9** |

差异题只有「水」「奶」两题，均为旧误判；**无新误判**。加表格逻辑后 9 题基线不变。

## 30 题验证（A 同数字异主体 / B 邻近 / C 否定）

最终 **30/30**，但**这个数没有区分力**：window=30/60/90 三档全满分，说明这批题压不到窗口边界。

## 真正的发现：标注是瓶颈

30 题里我自己标错了 **5 条**（17%）：

| 用例 | 我标的 | 原文实际 |
|---|---|---|
| p72 大豆 | 表里有 25~35g | 表里是 105~175g（每周） |
| p148 水 | 有数值，算答对 | 无具体数值 |
| p63 全谷物 | 不该算对 | 原文写「全谷物及杂豆50~150g」 |
| p43 运动 | 不该算对 | 原文写「每周150分钟以上」 |
| p72 全谷物 | 选错块 | 表格块判对了，选块函数先匹到别的块 |

**判分器本身 0 个 bug，5 个错全在标注。**

## 结论

1. 判分器可以上，9 题 9/9 站得住
2. **不扩 150 题**——标注错误率 17%，扩了就是把噪声放大 5 倍
3. 真要扩，先定「标注即证据」流程：每条 gold 必须附原文片段 + 页码，从块里直接抄，禁止凭记忆
4. 想验证 window，需要**对抗样例**（人工构造"值在 60 字内但属于别的主体"），从语料随手挑的题压不到边界
